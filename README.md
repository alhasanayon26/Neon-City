## 🌃 About the Project

**Neon City** is a browser-based, open-world 3D sandbox where players
can explore an urban environment on foot or behind the wheel. The game
combines free exploration with driving, missions, city activities,
weapons, shops, and player progression.

Rather than following only one path, players can choose how to spend
their time: explore the map, take a job, earn in-game currency, visit
shops, drive different vehicles, or simply roam the city.

The project is designed as a single HTML game file with its interface,
styles, and game logic bundled together. Three.js is loaded externally
from a CDN to provide 3D rendering.

### 🎯 Project Goals

-   Build an enjoyable city sandbox that runs directly in a modern web
    browser.
-   Bring together driving, exploration, action, and progression in one
    experience.
-   Make the game usable on desktop computers as well as compatible
    phones and tablets.
-   Keep the game easy to launch and share as an HTML file.
-   Continue improving controls, audio, visual effects, stability, and
    overall gameplay.

## 🚘 Vehicles and Driving

Vehicles are a major part of the Neon City experience. Available vehicle
types include cars, vans, trucks, motorcycles, and a city bus.

### 🏁 Driving Features

-   Accelerate, brake, reverse, and steer.
-   Use the handbrake for sharper turns and drifting.
-   Activate nitro where supported.
-   Use headlights and the horn.
-   Listen to different engine sound profiles across vehicle types.
-   Monitor fuel and refuel at petrol stations where the fuel system is
    available.
-   Use garage or mechanic features where supported.
-   Experience vehicle crashes and wreck effects.

### 🔊 Audio and Crash Effects

The game includes customised engine audio profiles and a deeper, less
piercing dual-tone horn. Crash-related effects are intended to appear at
the damaged vehicle or wreck, rather than at the player's character.

Audio playback can depend on the browser, device volume, and whether the
browser has allowed audio to start after a user interaction.

### 🚌 Bus Activities

A bus route activity is available in supported builds. Enter a bus and
use the in-game prompt or the driving controls listed below to start the
route.

## 📱 Mobile and Touch Controls

Neon City supports touch controls on compatible phones and tablets.

-   🕹️ Use the on-screen movement control to move on foot or steer while
    driving.
-   👀 Drag on the look area to rotate the camera.
-   🤏 Pinch to zoom where supported.
-   🦶 Use context-sensitive action buttons for movement and
    interactions.
-   🚘 While driving, use the **up-arrow button** to accelerate and the
    **down-arrow button** to brake/reverse.
-   📢 Use the on-screen horn control when driving.
-   ⚙️ Open the in-game menu to access settings and other options.

The exact layout can vary by device and game version. For the best
experience, use a modern mobile browser with JavaScript and WebGL
enabled.

## 💾 Save Data and Backups

Neon City includes save and backup tools for supported game progress.

### 💿 Saving Progress

-   Use the in-game **Save game** option to save progress to an
    available slot.
-   Autosave is available for supported progress; the in-game guide
    describes periodic autosaving.
-   Supported data may include currency, jobs, weapons, stalls, loans,
    outfits, and position.

### 📦 Exporting a Backup

1.  Open the game's menu or settings.
2.  Find the **Backup / restore** option.
3.  Export/download a backup file.
4.  Store the file somewhere safe, such as a cloud drive or another
    folder.

### ♻️ Restoring a Backup

1.  Open **Backup / restore**.
2.  Select the backup file you previously exported.
3.  Confirm the restore if prompted.

> ⚠️ **Important:** Restoring a backup may replace current saved data.
> Export a fresh backup before restoring an older one.

### 🧠 Browser Storage Notes

Some progress is stored locally in the browser. As a result:

-   Clearing browser site data may remove local progress.
-   Opening the game in another browser or on another device may not
    show the same save.
-   Private/incognito sessions may not retain data after they are
    closed.
-   Export a backup before clearing data, changing browsers, or moving
    to another device.

## 🚀 Getting Started

### Option 1 --- Open the HTML File

1.  Download the game HTML file from the project repository.
2.  Open it with a modern browser such as Chrome, Edge, or Firefox.
3.  Allow JavaScript and WebGL if prompted or disabled.
4.  Click or tap the game screen to begin and enable audio if the
    browser requires a user interaction.

### Option 2 --- Run a Local Web Server

A local server can provide a more consistent environment than opening a
file directly. From the directory containing the HTML file, run a simple
static server using a tool available on your computer, then open the
local address it provides.

For example, if Python is installed:

``` bash
python -m http.server 8000
```

Then open `http://localhost:8000` in your browser and select the game
file, or name the main HTML file `index.html`.

### 🌐 Hosting Online

1.  Upload the HTML game file to your web host or repository.
2.  If your host serves static sites, configure the game file as the
    landing page (often `index.html`).
3.  Ensure the site can access the external Three.js CDN dependency.
4.  Test the published game on both desktop and mobile browsers.

**Network note:** The current build loads Three.js from a CDN, so an
internet connection is required for that dependency unless the project
is changed to bundle it locally.

## 🛠️ Troubleshooting

### The game does not load

-   Use a modern browser with JavaScript and WebGL support.
-   Check your internet connection because Three.js is loaded
    externally.
-   Reload the page and try again.
-   If hosting online, confirm the HTML file and CDN dependency can be
    reached.

### The game is slow or stutters

-   Close other resource-heavy browser tabs.
-   Reduce graphics settings if the game provides them.
-   Try a browser with better WebGL performance.
-   On mobile, close background apps and allow the device to cool if it
    is overheating.

### There is no sound

-   Check device volume and browser tab mute settings.
-   Check the game's audio settings.
-   Tap or click the game before testing sound; some browsers restrict
    audio until user interaction.
-   Try reloading the game after interacting with the page.

### My progress is missing

-   Check whether you are using the same browser and device as before.
-   Check whether browser data was cleared or the game was opened in a
    private session.
-   Restore a backup only if you have a valid exported file, and back up
    current data first.

### Mobile controls do not respond

-   Confirm the page has finished loading.
-   Try rotating the device or reloading the page.
-   Make sure the browser is not blocking touch interaction or scripts.
-   If a control behaves differently than expected, include your device,
    browser, and a short description when reporting the issue.

## 🤝 Contributions and Feedback

Ideas, bug reports, and improvement suggestions are welcome.

When reporting a bug, please include:

1.  **What you expected:** What should have happened?
2.  **What happened instead:** Describe the actual behaviour.
3.  **Steps to reproduce:** List the actions that trigger the issue.
4.  **Device and browser:** For example, Android + Chrome or Windows +
    Edge.
5.  **Screenshot or recording:** Include one when it helps explain the
    problem.

For code changes, keep the existing game behaviour intact unless a
change is intentional. Test both desktop and mobile layouts when
possible, especially after editing controls, menus, audio, save systems,
or collision effects.
